# 架构与行为约束

本文记录 Port Sentinel 的设计意图、长期边界与行为契约，供修改相关功能时判断取舍。当前实现与可执行接口仍以代码、类型和测试为准；发现两者冲突应明确解决，不能将现有实现自动视为设计变更。运行、构建与验证方法见[开发与发布](development.md)。

## 产品与技术边界

Port Sentinel 是本地桌面工具，核心任务是查看端口与连接、定位占用进程，并在用户确认后操作目标进程。保留 TCP/UDP、IPv4/IPv6、搜索、筛选、排序、复制、详情和单个/批量操作。关闭窗口即退出，退出时停止后台任务并清理按需辅助进程；设置保存失败时先显示错误，由用户决定是否放弃保存退出。无托盘、后台驻留、自启动或账号系统。

Go 负责系统能力和业务状态，Wails v2 提供生命周期与桌面桥接，React/TypeScript 与 HeroUI 负责展示和交互。平台 API 与命令隔离在适配层，业务层组织扫描、进程操作和设置；桥接层保持轻量，前端不承担系统权限判断。仓库必须独立安装、构建和运行。

支持目标为 Windows 10/11 amd64、macOS 12+ Intel/Apple Silicon 和 Ubuntu 22.04/24.04 amd64 桌面。支持目标与实际验收分开记录，其他 Linux 发行版不能据此声称全面兼容。运行依赖见 [README](../README_zh.md)。

macOS 使用系统 WebView，最低系统版本同时约束前端语法、CSS 和组件库。当前保留 Tailwind 3.4、HeroUI 2 与 Safari 15 构建目标，是为兼顾 macOS 12；具体依赖版本见包配置。升级这些依赖时应重新核对旧 WebView，单改 Info.plist 或构建成功不足以证明兼容。构建目标与链接兼容处理见开发文档。

## 连接数据与任务状态

- 区分 TCP 监听/UDP 绑定与全部连接，显示本地/远端地址、状态、PID、进程名和可读路径。信息不可读、进程已退出、无关联 PID 与扫描失败必须分别表达。
- 普通扫描与授权扫描需标记来源。授权代表本次扫描经过系统授权，不保证受保护进程全部可见；后续普通刷新也不继承授权范围。
- 扫描失败保留上次成功数据并标记过期，授权取消同样保留已有数据。加载、空列表、筛选无结果、部分可见、取消和错误应可区分。
- 扫描、进程操作和下载不得阻塞界面。控制任务重叠、取消及结果顺序，过期结果不能覆盖新状态。自动刷新不得弹出授权请求。

筛选、刷新间隔与其他设置的默认值和有效范围以 [settings 定义](../internal/settings/settings.go) 为准，避免在多份文档维护参数表。

## 权限与进程操作

主界面默认以普通权限运行。用户主动授权扫描，或已确认的进程操作遇到权限不足时，通过 Windows UAC、macOS 系统管理员授权或 Linux polkit 启动独立辅助进程。这样将高权限能力限定在当前操作，避免让整个 WebView 获得高权限。不安装常驻高权限服务，不收集或保存管理员密码，也不跨操作持久保存授权状态。

辅助进程只能接受明确的扫描或结束进程请求，不能成为任意命令入口。必须验证请求参数、调用来源和结果通道，隔离各次请求并清理资源。取消授权、权限不足、授权组件缺失和系统保护导致的失败要显式反馈，不绕过系统保护。

进程操作遵守以下契约，以降低误杀与影响范围不明的风险：

- 确认前展示 PID、进程名和关联端口，说明操作影响该进程全部连接，包括未选中端口。批量目标按 PID 去重，一次批量操作按需为权限不足的目标集合授权。
- 保存并在执行前复核进程身份，不能把 PID 当成跨时间稳定身份；刷新后选择也不能因行位置或 PID 复用而转移。拒绝危险的无效 PID、应用自身和辅助进程目标。
- 默认请求正常退出。不支持或仍在运行时明确反馈；强制结束必须另行确认，不超时后自动强制结束，也不默认递归结束进程树。
- 发送退出请求成功不代表进程已退出。逐进程报告成功、失败、已退出或仍在运行等结果，操作后重新扫描实际连接，不能先删行伪造成功。

Windows 正常退出依赖目标能接收窗口关闭请求，没有适用窗口时应报告不支持正常退出。平台能力差异应显式表达，不能用强制结束替代正常退出契约。

## 界面与国际化

保留以端口表格为核心的工具布局：顶部为搜索、连接范围、协议、刷新及独立授权扫描入口，主体为固定表头的可滚动表格，底部为条目数、刷新时间和扫描状态。窄窗口优先保留端口、协议、PID、进程与操作，其他信息通过详情查看。重大产品范围变化才重新评估布局。

进程名称打开详情侧栏，名称不可读时仍保留入口。详情展示名称、PID、可复制完整路径和关联端口。全选限定当前筛选结果，批量操作区展示去重进程数和关联端口。设置按“常规 / 关于”组织偏好、构建信息与更新操作。

支持浅色、深色、跟随系统主题，以及跟随系统、简体中文和 English 语言设置。中文系统使用简体中文，其他语言使用英文；切换立即生效并保存。用户可见文案集中管理，日期与数字按当前语言格式化，进程名、路径、地址和协议保留原值。后端以稳定错误标识及必要上下文表达业务错误，前端本地化摘要，保留原始系统错误供排查。

通过布局、间距、对齐和层级组织信息，避免装饰性卡片、营销文案和重复说明。保留键盘操作、焦点反馈和可访问名称，关键状态不能只靠颜色区分。

## 设置与程序更新

设置存储在当前用户配置目录。持久化偏好与窗口大小，不跨启动保存搜索词、勾选项或授权状态。损坏配置和写入失败必须可见，不能静默覆盖损坏原文件；允许带错误提示使用默认值继续当前会话。恢复方式见开发文档。

更新限定于本项目正式 Release 和匹配平台的附件。正式构建允许周期或手动检查，发现新版本只标记入口；下载、替换与重启必须经用户确认，下载可取消。开发构建禁用检查和安装，避免测试时替换开发程序。具体定时策略见 [app.go](../app.go)，默认开关见 settings 定义。

下载失败不能导致应用退出；替换或新版启动失败时尝试恢复旧程序。新版窗口完成初始化才能确认启动成功，不能将启动命令成功视为升级成功。安装目录不可写时显示错误并提供手动下载，不复用进程操作的提权流程更新程序。

签名与公证状态必须如实表达。未经签名或公证的包可以发布，但构建和自动化测试不能替代签名包安装、真实授权或已安装程序升级验收。发布与签名约束见开发文档。
